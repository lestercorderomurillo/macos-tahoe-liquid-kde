## Issue #85: sudo session environment

The shared session recovery helper treated empty environment entries as
explicit values and trusted inherited runtime paths without checking ownership
or existence. It also guessed runtime sockets before reading Plasma's actual
environment, which prevented recovery of custom session paths and addresses.

Recovery now treats empty entries as missing, rejects invalid or foreign-owned
runtime directories, and fills missing values from the invoking user's Plasma
process before falling back to runtime sockets. Explicit valid session values
remain authoritative. The CLI already calls this helper after its effective
UID/GID drop and before preflight or any installation step. OLED retirement
continues to retain recovery state when service-manager access fails.

Thirteen added regression cases cover absent/empty/stale/relative runtime
values, ownership, custom Plasma runtime and bus selection, explicit overrides,
the process-environment allowlist, inaccessible `/proc`, non-socket bus files,
and delivery of the recovered environment to OLED and theme-switch service
commands through `run_user`. Seven failed against the baseline and passed
after the fix. An existing theme-switch test was also isolated so recovered
XDG paths cannot leak into subsequent preflight tests.

A separate native check ran both helper revisions against a private
`dbus-daemon` and queried `org.freedesktop.DBus.ListNames` with `dbus-send`
through `run_user`. Bubblewrap isolated the process and network namespaces,
provided private `/run` and `/tmp`, cleared inherited environment variables,
and mounted the host filesystem read-only.

| Environment | v0.51.2 | Fixed |
| --- | --- | --- |
| Both session variables absent | Bus reachable | Bus reachable |
| Both session variables empty | Connection failed | Bus reachable |
| Runtime directory nonexistent; bus address absent | Connection failed | Bus reachable |

This proves native DBus recovery for the discovered failure paths. It does
not reproduce the reporter's Fedora 44 session or run a full privileged
installation. The report does not distinguish absent from empty/stale values;
entirely absent variables already worked in the baseline's standard runtime
case. Service operations in regression tests use captured subprocess calls,
so no live OLED timer or desktop geometry is changed during validation.

## PR #84: reduce default blur work

The strength-3.5 preset contribution is from
[@myakupozluk's PR #84](https://github.com/lestercorderomurillo/macos-tahoe-liquid-kde/pull/84),
head `6799753fd0eeda91f08ec04d5d69f6789863241c`. The complete diff was reviewed
before accepting the change: two ordinary Python files, eight additions and
two deletions, with no dependency, build, workflow, binary or symlink changes.
Only the proposed preset and associated regression expectation were adopted;
contributor-provided verification commands were not executed.

The installer now writes strength `3.5`, matching `glass.kcfg`. An additional
test exercises the real install function with file installation and DBus
boundaries stubbed, and compares its captured `kwriteconfig6` arguments with
the bundled effect's default. Both preset tests failed with strength `5`.

A native C++ probe compiled the table builder and strength-decoding portion
of the bundled `effect.cpp` verbatim against Qt6Core, using a minimal facade
for the effect/configuration interfaces. It produced:

| Strength | Kawase downsample levels | Damage expansion |
| --- | --- | --- |
| 3.5 | 2 | 20 |
| 5 | 3 | 50 |

This confirms reduced configured rendering work; it is not a GPU frame-time
benchmark or visual comparison in a running KWin session.
