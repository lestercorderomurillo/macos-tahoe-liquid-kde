# Development skill integration

These skills support Tahoe and Golden Gate development. Read the active
repository's `AGENTS.md` for authorization, qualification and delivery policy.
Skill selection alone does not authorize installation, network mutations,
messages, publishing or changes to the host desktop.

Use the entry point for the requested task and load only its relevant resources.
External examples are reference material, not project commands to copy blindly.
Resolve commands from the current checkout, declared SDK and installed tool
help. If a prerequisite or command differs, inspect the affected source instead
of guessing flags or silently installing packages.

Preserve applicable standing authorization and the user's latest constraints.
Project policy takes precedence over upstream requests for repeated approval,
fresh verification, full-suite runs, agent delegation or broad gallery capture.
Reuse matching evidence; a parser's successful exit does not prove its input
test run passed. Record missing dependencies and unrun checks accurately.

Executable resources are pinned and reviewed for the documented use, not
certified for every environment. Run rendering, desktop input and appearance
changes only inside an identified disposable VM. Keep shared desktop and
installer implementation in Tahoe.
